# Sprint 2 Retrospective

## Summary

Sprint 2 focused on closing out the basic user stories and starting on intermediate functionality. By the end of the sprint we had delivered the core gameplay loop (events, location verification, challenges, cards) and begun intermediate features (offline support, anti-spoofing, PvP, trails).

**Outcome:** 85% from the client review — a strong improvement.

## What went well

- **All basic user stories were completed.** The core gameplay loop is now working end-to-end.
- **Several intermediate user stories were delivered** ahead of schedule.
- **Client score improved significantly** (63% → 85%), reflecting better alignment with expectations.
- **Meetings and communication improved.** Blockers were caught earlier than in Sprint 1.
- **Documentation began catching up** with the codebase.

## What didn't go well

- **Some duplicated effort.** Two teammates started work on the same area before realising they were overlapping. This cost time that could have been spent on other features.
- **Communication at the start of implementation** — kickoff announcements about what each person was working on weren't consistent, so overlaps weren't caught until mid-sprint.
- **Some user stories landed late**, leaving less time for polish and testing than planned.

## Actions for Sprint 3

- **Announce work before starting it.** Each team member posts what they're picking up at the start of implementation, so overlaps are caught immediately.
- **Keep meetings regular** — the cadence from Sprint 2 worked; keep it.
- **Target the advanced user stories** now that basic and intermediate are in good shape.
- **Add a theme change to the UI** as a smaller polish item alongside the advanced features.
- **Push for the 90s** on the client score.
