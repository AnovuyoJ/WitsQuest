# Sprint 3 Retrospective

## Summary

Sprint 3 focused on completing the advanced user stories and polishing the UI. By the end of the sprint we had delivered the remaining features (live PvP, trust and moderation, procedural events, competitive ratings, zone control, trading, analytics) and added a theme change to the UI.

**Outcome:** 95% from the client review — the highest score across the three sprints.

## What went well

- **All advanced user stories were completed.**
- **Theme change was added** as a UI polish item.
- **Client score hit 95%**, confirming the team's progress across the three sprints.
- **Communication improved** from Sprint 2 — overlapping work was rare, and meetings were productive.
- **Documentation was kept up to date** with the new features.
- **Team confidence and cohesion** grew noticeably over the sprint.

## What didn't go well

- **Testing was compressed** toward the end of the sprint, as feature work ran close to the deadline.
- **Some documentation was updated late**, catching up after features had already been merged.
- **UI consistency** across newly added pages could be more uniform.

## Actions for the next cycle

- **Start documentation alongside feature work**, not after it, so it doesn't become a catch-up task.
- **Reserve time in the sprint for testing and polish** rather than filling the entire sprint with feature work.
- **Review UI consistency** across older and newer pages to unify styling and behaviour.
- **Consider a light design review** before final submission to catch any remaining rough edges.
