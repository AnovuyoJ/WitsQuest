## Meeting 3 — User Testing, Client Feedback and Documentation

**Date:** 8 September 2026

**Attendees:**

* Busisiwe Dlamini
* Lerato Sikhumbana
* Anovuyo Dlamini

### Discussion:

### 1. **User Testing**

* The team discussed the Sprint 2 requirement to conduct testing with external users.
* We agreed to recruit external users to test the game.
* A questionnaire will be used to collect structured feedback from the testers.

### 2. **User Feedback**

* The team agreed that feedback should focus on:

  * Ease of navigating the application.
  * Understanding how quests and challenges work.
  * Location-based functionality.
  * Game usability.
  * Problems or bugs encountered while playing.
* At least one concrete improvement should be made to the application based on the feedback received.

### 3. **Client Engagement**

* The team discussed keeping evidence of client meetings.
* Screenshots and detailed meeting notes should be retained as evidence.
* Feedback received from the client should be documented together with any changes made as a result.

### 4. **Database Documentation**

* The team agreed that the database documentation should include:

  * All database tables.
  * Columns and data types.
  * Relationships between tables.
  * An ER diagram.
  * Database deployment information.
  * Explanations for important database design decisions.

### 5. **API Documentation**

* The team discussed documenting the application's API endpoints.
* Each endpoint should document:

  * What the endpoint does.
  * HTTP method.
  * Required authentication.
  * Request format.
  * Response format.
  * Possible errors.

### 6. **Third-Party Libraries**

* The team agreed to review the project's `package.json` files.
* External libraries and packages used by the project should be documented together with the reason each was selected.

### Action Items:

* Recruit external users to test the application.
* Collect user feedback using the questionnaire.
* Document changes made based on user feedback.
* Complete the database documentation and ER diagram.
* Continue documenting API endpoints.
* Document external libraries and their purposes.
* Collect evidence of client meetings and feedback.
