## Meeting 1 — Sprint 3 Planning and Rubric Review

**Date:** 16 September 2026

**Attendees:**

* Busisiwe Dlamini
* Lerato Sikhumbana
* Anovuyo Dlamini
* Thabo Maleke

### Discussion:

### 1. **Sprint 2 Review and Feedback**

* The team reviewed the progress made during Sprint 2 and discussed feedback received from the previous milestone.
* The team identified the need for stronger evidence of user testing, automated testing, and documentation.
* The team agreed that feedback should be incorporated into the Sprint 3 development process rather than only being addressed at the end of the sprint.

### 2. **Sprint 3 Rubric**

* The team reviewed the Sprint 3 rubric and identified the main areas that would require evidence throughout the sprint.
* Particular attention was given to:
    * User feedback and testing
    * Automated testing and code coverage
    * Feature implementation
    * API implementation
    * Performance
    * Improvement based on feedback
    * Project documentation
    * Project methodology

### 3. **Sprint 3 Features**

* The team reviewed the remaining feature requirements and prioritised the features to be implemented during the sprint.
* Procedural event distribution was identified as a feature to improve the way events are placed across campus.
* The team discussed the importance of ensuring that generated events are appropriately spaced and that events can rotate over time.
* User stories and tasks were added or updated on the Taiga backlog

### 4. **Testing and Quality Assurance**

* The team agreed that automated tests should be written alongside feature implementation rather than after development is completed.
* Backend services, API routes, and relevant frontend components will be tested.
* The team agreed to monitor test coverage and address bugs identified during testing.

### 5. **Documentation**

* The team agreed to improve documentation throughout the sprint.
* Documentation will cover the implemented features, APIs, database changes, testing, and relevant third-party technologies.
* The team agreed that technical decisions should be recorded so that the implementation can be clearly explained during the milestone assessment.

### Action Items:

* Finalise the Sprint 3 backlog and assign user stories.
* Begin implementation of the prioritised Sprint 3 features.
* Add automated tests alongside feature development.
* Gather user and stakeholder feedback during development.
* Record bugs and improvements in Gitea Issues.
Begin updating technical and project documentation.
